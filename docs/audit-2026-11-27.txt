ИСПРАВЛЕНО
1. Убраны отсечения сканера на 300 лотах и анализатора на 30 подарках.
   Фоновая задача обходит страницы постепенно, сохраняет offset в PostgreSQL,
   отдельно проверяет начало ленты. Размер шага соответствует фактическому ответу API.
   Результаты дедуплицируются по market/external_id.
2. Добавлен FairValueEngine: сопоставление коллекции, модели, фона, символа,
   редкости и категории номера; медианы/квартили, вес давности продаж,
   IQR-фильтрация выбросов. Общий floor коллекции не используется как цена выхода.
3. При отсутствии достаточных аналогов стоимость и прибыль равны null,
   отображается «Недостаточно данных». Объявления не считаются продажами.
   Сценарии на одних объявлениях имеют низкую достоверность и не попадают
   в прибыльные сигналы/рассылку. Для сигналов нужны продажи либо исполнимый офер.
4. Убран произвольный дисконт 5% из оценки. Сценарии берутся из распределения аналогов.
   Все денежные вычисления используют Decimal. Базовая комиссия Portals для новых
   настроек — 2% (официальная документация); существующие настройки не перезаписываются.
   Комиссии относятся к перепродаже внутри площадки, без вывода в кошелёк.
5. Бюджет является верхней границей полной стоимости приобретения.
   Отдельный лимит одного подарка применяется только при явном включении.
6. Поиск читает готовые оценки из базы. Сессия поиска фиксирует идентификаторы
   на 10 минут, возвращает общее количество и сохраняет страницы при новых лотах.
7. Перепроверка принимает идентификатор лота каталога и идентификатор сигнала,
   проверяет источник, обновляет цену/оценку и карточку. Исчезнувший лот отличен
   от недоступности API (503). Для HTTP используется общая сессия и ограничитель.
8. Портфель: добавление из каталога, ручной ввод, исправление стоимости,
   закрытие продажи, удаление, история операций и изоляция пользователей.
   Отсутствующая оценка не превращается в нулевую прибыль.
9. Диагностика администратора: уникальные лоты/коллекции, свежие данные,
   причины исключения, время анализа; API также отдаёт курсор, ошибки и задачи.
10. Добавлен отдельный раздел наблюдения за лотами в бюджете.
11. Исправлена повторная заявка перевода для разных сроков подписки;
    начальная цена длинных тарифов берётся из сохранённой месячной цены.
12. Публичный endpoint демо больше не отдаёт искусственные цены.

LUCKY LOCKET 129
Старый код при нехватке аналогов переходил к ценам всей коллекции и выбирал
между floor и нижним квартилем. Поэтому редкий вариант мог оцениваться как обычный.
Если ориентир был около 17,27, прежняя формула 17,27*0,95*0,975-129 давала около -113.
Это иллюстрация найденной ошибки, не восстановленная история конкретного лота:
UUID, исходный ответ и точные настройки той карточки не предоставлены.
Регрессионный тест: лот129, floor16, аналоги с другой моделью -> неизвестная
оценка, а не прогноз убытка113.

ОГРАНИЧЕНИЯ И ОСТАВШАЯСЯ РАБОТА
- Полный рынок НЕ подтверждён: offset-пагинация движущейся ленты может пропускать
  лоты; API может ограничивать глубину. Обход продолжается, свежесть каталога15мин.
  Отдельного доказанного обхода каждой коллекции пока нет.
- WebApp-токен в текущем адаптере не предоставляет историю сделок.
  Для подтверждённых оценок нужен проверенный доступ к Partners API/продажам.
  Даже официальный market/actions ограничивает offset700; вся история не обещается.
- Регрессия премий отдельных характеристик и оценка по неполным совпадениям
  пока не реализованы. Редкий подарок без точных аналогов останется без оценки.
- Срок перепродажи неизвестен. Ликвидность — число доступных сопоставимых продаж,
  не вероятность продажи. Пользователи сделок обезличены, wash trading не исключён.
- Нулевые комиссии отдельных коллекций требуют данных/настройки. Настроенная
  стандартная комиссия2% может завышать расходы для таких коллекций.
- Итоговая стоимость портфеля и общая доходность при неизвестных оценках
  не могут быть достоверно показаны; полноценный учёт свободного кошелька не подключён.
- Ссылка покупки, реальная глубина API, нагрузка большого рынка и свежий токен
  требуют live-проверки. Тесты не подтверждают возможность заработка.
- MRKT остаётся отключённым. Автоматической торговли нет.
- Историческая миграция0005 включала уведомления существующим пользователям.
  Новое обновление их настройки не меняет; неизвестные прежние отказы не восстановлены.
