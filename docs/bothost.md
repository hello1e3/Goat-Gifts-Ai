# Развёртывание в Bothost

## 1. Создайте бота

В Telegram откройте @BotFather, отправьте `/newbot`, задайте имя и username. Сохраните токен в менеджере секретов. Узнайте числовой Telegram ID владельца из доверенного источника, например из собственного тестового взаимодействия с Bot API.

## 2. Загрузите исходники в GitHub

Создайте пустой приватный репозиторий. В корне проекта выполните:

```bash
git add .
git commit -m "Add GOAT Gifts AI"
git branch -M main
git remote add origin git@github.com:OWNER/REPOSITORY.git
git push -u origin main
```

Для первого коммита Git может запросить имя и адрес автора. Файл `.env.example` предназначен для репозитория. Настоящие параметры задаются в панели Bothost.

## 3. Подключите Bothost

В панели создайте приложение Telegram и подключите репозиторий и ветку `main`. Выберите стек Dockerfile. Используйте корень репозитория как контекст сборки. Образ собирает frontend на Node 22 и запускает приложение на Python 3.12 по команде `python start.py`. Docker Compose предназначен для локальной среды.

## 4. Укажите параметры

| Параметр | Значение |
|---|---|
| `BOT_TOKEN` | Токен BotFather |
| `ADMIN_IDS` | Числовые ID через запятую |
| `ENVIRONMENT` | `production` |
| `PORT` | Внутренний порт из настроек, например 8000 |
| `APP_URL` | Полный публичный HTTPS-адрес терминала |
| `DATABASE_URL` | DSN PostgreSQL |
| `DEFAULT_SUBSCRIPTION_PRICE_XTR` | Начальная стоимость в Stars. Пустое значение закрывает продажи до задания цены |
| `PURCHASE_APPROVAL_REQUIRED` | `true` для ручного одобрения первой конфигурации |
| `NEWS_CHANNEL_URL` | HTTPS-ссылка на новости, по желанию |
| `WEBHOOK_URL` | Полный HTTPS-адрес `https://домен/telegram/webhook` или пусто для long polling |
| `WEBHOOK_SECRET` | Случайная строка из букв, цифр, `_`, `-`, минимум 24 символа для webhook |
| `PORTALS_API_KEY` | Ключ после согласования использования данных |
| `PORTALS_DATA_LICENSED` | Подтверждение прав владельцем, по умолчанию `false` |
| `MRKT_API_KEY` | Зарезервировано для партнёрского адаптера |
| `REDIS_URL` | Зарезервировано. PostgreSQL обслуживает очередь и общий кэш |
| `RUN_BACKGROUND` | `true` для первого экземпляра |

Начальная цена и режим ручного одобрения применяются при создании тарифа. После этого ими управляет база через команды владельца.

## 5. Подключите PostgreSQL

Используйте PostgreSQL из панели, если он доступен на выбранном тарифе, либо внешнюю управляемую PostgreSQL с сетевым доступом от Bothost. Для внешнего сервиса задайте DSN с TLS по инструкции своего провайдера, например параметром `ssl=require` для asyncpg. Роль приложения должна иметь права миграции в выделенной базе. Приложение запускает Alembic и блокирует параллельные миграции через PostgreSQL.

## 6. Настройте HTTPS

Включите использование домена и укажите порт контейнера, совпадающий с `PORT`. FastAPI слушает `0.0.0.0`. Bothost принимает HTTPS и проксирует HTTP в контейнер. Поддомен, PostgreSQL, Redis и лимиты проверяйте на выбранном тарифе. Для локальных файлов Bothost документирует `/app/data`. Приложение хранит состояние в PostgreSQL, изображения демо входят в образ.

## 7. Запустите приложение

Разверните выбранную ветку. Проверьте журналы сборки и запуска. Запрос `GET /health` должен вернуть `{"status":"ok"}`. Основной адрес должен открыть торговый терминал. Отправьте `/start` боту. В случае ошибки 502 проверьте настройки домена, порт и логи старта до изменения конфигурации Telegram.

## 8. Проверьте Mini App

При заданном `APP_URL` бот выставляет кнопку меню. При желании настройте основной Mini App для того же адреса через BotFather. Откройте терминал кнопкой бота и проверьте имя и Telegram ID. На публичном адресе в обычном браузере должен отображаться гостевой режим.

## 9. Проверьте подписки

Войдите со второго Telegram-аккаунта. Главная и сканер должны показывать демо. Выдайте тестовый доступ через `/admin → Выдать доступ`, подтвердите и откройте терминал снова. Проверьте отзыв, заморозку и разблокировку.

## 10. Проверьте оплату

Сначала используйте выделенного тестового бота Telegram. Установите цену, проверьте ручное одобрение до выставления счёта, затем оплату, продление, статистику и возврат. Перед публичным запуском внесите реквизиты оператора и правила в `/legal`. Убедитесь, что `/paysupport` открывает платёжную поддержку.

## 11. Проверьте права и резервные копии

С аккаунта из `ADMIN_IDS` откройте `/admin` и владельческую страницу Mini App. Проверьте, что второй аккаунт видит только свои данные. Настройте резервное копирование PostgreSQL. Выполните тест восстановления в отдельную базу. После запуска и подключения GitHub приложение работает в контейнере Bothost независимо от компьютера владельца.

## Резервное копирование и ресурсы

Запускайте `scripts/backup.sh` с `DATABASE_URL` на машине с `pg_dump` и `pg_restore` версии PostgreSQL не ниже версии сервера. Основная копия должна храниться вне контейнера. Для восстановления используйте пустую проверочную базу и `pg_restore --no-owner --no-acl --exit-on-error`. Храните копии с отдельными правами доступа и согласованным сроком хранения.

Bothost документирует 256 МБ на бесплатном тарифе, 1 ГБ на базовом и 2 ГБ на Pro. Для выбора тарифа измерьте память и задержки на выбранной конфигурации. Начните с одного контейнера. API и очередь используют общий PostgreSQL. Для нескольких экземпляров применяйте webhook и одну конфигурацию токена. Глобальный сканер и планировщик выбирают лидера через advisory locks, очередь резервирует записи через `FOR UPDATE SKIP LOCKED`. Используйте прямое подключение PostgreSQL или пул с поддержкой сессионных блокировок.
